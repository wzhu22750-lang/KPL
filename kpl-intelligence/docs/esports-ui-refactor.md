# KPL 赛事数据 UI/UX 重构交付与验收

本轮重构九个既有赛事页面，以英雄榜和英雄档案建立可扩展的体育编辑式数据界面。没有修改 API、采集、评分、统计、数据库或品牌配置，没有新增依赖。

> **验收边界**：前端类型检查、构建、48 项 Web 测试、14 项真实数据浏览器交互及 108 个生产界面状态通过。后端数据库测试因本机 PostgreSQL 不可连接而无法启动，不能认定后端全套测试通过。KDA / 伤害占比仍存在接口默认值与样本缺失问题，已在页面明确披露，未改后端规则。

## 统一设计系统

### 视觉与信息层级

采用 **Modern Esports Editorial Dashboard**，不是游戏客户端或宣传海报。

- 保留浅色暖纸、深色炭灰、青绿色 / 青色品牌语义 token，以及原系统字体、侧栏与手机壳。
- 内容最大宽度 1280px；用克制的顶部强调线、淡色分区和头像建立竞技感，不使用新霓虹、光晕、毛玻璃或大图背景。
- 排名、角色名称、战队身份与结果为第一层；BP、胜率、积分等为第二层；出场样本、口径、赛季和筛选为第三层；关系、赛制、履历、报道和完整 BP 为深入层。
- 主要数字约 24–40px，次级指标与单位分开；统一等宽数字对齐。圆角沿用 control/card/panel/sheet 语义尺度。
- T0 / T0.5 为温和琥珀色，T1 为品牌强调，其余为中性色；梯度不压过真实 BP 和胜率。
- 红蓝阵营是独立语义色，不用胜率高低模拟红蓝阵营。队徽在深浅主题都有中性衬底，避免透明深色 Logo 消失。

### 共享模块

`app/components/esports/Esports.tsx` 提供：

| 组件 | 使用范围 / 职责 |
| --- | --- |
| `EsportsNav` | 连通五个现有赛事入口；父级归属、当前状态及导航进行中反馈 |
| `PageHeader` | 标题、说明、档案分类及紧凑操作，不抽象业务查询 |
| `Portrait` | 英雄 / 战队 / 选手图片，固定尺寸、懒加载、错误和水合前失败降级 |
| `Metric` | 主次数据、单位和样本说明 |
| `TierBadge` | 已有梯度字段的统一语义展示；未知值为未评级 |
| `RateBar` | 独立比例刻度、0 / 100 边界、可访问 meter 名称与数值 |
| `MatchRow` | 双方身份、比分、真实服务端状态、北京时间和档案链接 |

`app/lib/esports.ts` 只处理显示：null / 非有限数为 `—`；真实零保留；无出场样本不制造胜率；超出 0–1 的百分比不绘制虚假柱长；比例不设置虚假的最短长度。没有改排序、梯度或统计算法。

动效限于交互颜色 / 边框 / 微阴影反馈，沿用全站 reduced-motion 规则。键盘焦点、按下反馈与触屏操作均保留，没有把 hover 当作唯一入口。

### 手机与平板

- 英雄榜默认为一列可触控排名卡，641px 以上按可用空间增加列数；不是把桌面四列压缩到小字号。
- 英雄档案手机用紧凑并置身份区；两核心比例和单独样本区，次数据纵向阅读。
- 积分榜表格行在 768px 以下按标签重排，核心积分和队名无需横滚；没有复制另一套排行榜计算逻辑，也没有隐藏任何数据单元。
- 赛程与 H2H 选择器在手机单列，比赛比分卡可直接阅读；所有 BP 步骤保留，可用原生 details 展开 / 收起，不以删步骤适配。
- 768 / 1024px 都实际检查；保留全站 961px 的 shell 切换断点，不另外重写侧栏。

### 实测中发现并处理的失败

- 共享组件尚未创建时，开发服务器缓存了一次模块缺失；组件落地后重启开发服务器恢复。
- 第一轮 Web 回归 43 / 44 通过：积分组标题中新增空格不符合既有 SSR 断言；恢复连续语义标题后 48 / 48 通过，没有删改原测试。
- 首轮交互固定等待不足以覆盖远端读取，改为等待导航完成。随后确认两项真实缺陷：StrictMode 提前消耗滚动恢复记录、SSR 图片失败早于水合；分别修正消费时机和完整图片状态检查后全部通过。
- 生产验证初次选用的 3100 端口已有其他进程，启动失败且误访问既存服务，得到 108 个错误页。该失败 JSON 单独保存在 `failed-production-port3100.json`；未结束原有进程。独立 3123 进程最终完整复验通过，画廊只引用最终成功截图。
- 320px 人工视觉检查发现装饰头像可能覆盖样本说明，改为真实网格分配空间；再次生产截图无重叠。

## 未解决的数据口径与后续建议

这些不是本轮擅自修改的业务规则：

1. `packages/backend/src/kb/read.ts` 在英雄场均 KDA 缺失时默认 **3.0**、伤害占比缺失时默认 **20%**；契约不含来源 / 有效记录数。页面标明“接口值”和默认值，不能将其解释为完整实测。
2. 同文件经济占比固定为 **20%**，本轮没有将它展示为真实指标；后续需有真实查询及契约后才开放。
3. 红蓝各侧缺少独立出场数；接口用 0 表示无该侧记录。页面说明 0% 可能是无记录，不据此断言选边优势。
4. “克制”查询实为对方阵容共现胜率，并非严格同分路对位，也不证明因果。界面与描述改用对方阵容交手记录。
5. 版本梯度可能来自已有资料字段或 BP 历史阈值，并非有明确当前版本时间窗的能力模型。原评定规则不动，页面标注历史汇总。
6. 选手契约没有独立比赛记录列表 / 头像背景大图 / 综合能力模型，因此仅组织已有赛季、英雄和动态，不编造新模块。
7. 统一赛事中心的全站导航尚未落地。本轮只连接既有入口；后续导航信息架构应统一调整 sidebar / bottom tabs / more，而不是重复新增另一套中心路由。
8. 可在本地数据库可用后补跑后端全套测试；另补实际触屏设备、Safari、屏幕阅读器和 Lighthouse。当前自动化使用 Chromium，不能等同于跨浏览器认证。
9. 已收录 honor、战队状态、肖像所属及历史阵容的业务准确性仍由现有数据负责；本轮保留，不自行“纠正”成未经核实的新数据。
