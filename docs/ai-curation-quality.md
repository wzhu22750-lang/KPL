# AI 精选运行与验收说明

> 本次升级的是 Python → kpl_vault 入库路径，不是主站全部多源精选系统。模型调用默认关闭。阈值为待人工样本校准的初值。历史库存保留，不会自动重审或撤下旧低质内容。

## 新流程

```text
候选URL → 页面/正文检查 → 规则相关性、非KPL、广告与垃圾过滤
  → 全文＋来源声明＋真实发布时间＋当前时间＋正文重复状态
  → LLM 六维 JSON → 严格校验 → 代码按类型加权/噪声扣分/准入
  ├─ 低价值：拒绝并记录质量评价
  ├─ 模型关闭/故障/非法输出：待复核（不自动放行）
  └─ 合格：库外暂存下载 → 核对正文、标题、作者一致
       → 增量写metadata → 发布归档目录 → 索引/审计
```

新目录首次发布用同文件系统 rename；既有同来源目录更新保持原有资产。无全库清空操作。所有二次下载在临时目录内，失败会清理临时文件。候选来源格式和 scrape_article 接口不变。

## 启用方式

在仓库根目录运行。环境变量需由 shell 或进程管理器注入；本评分器不自动读取 `.env`。

| 变量 | 含义 |
|---|---|
| KPL_QUALITY_MODEL_CALLS_ENABLED | 只有精确字符串 true 才启用外部模型请求 |
| KPL_QUALITY_API_BASE | OpenAI-compatible API base，包含服务要求的 /v1 等前缀 |
| KPL_QUALITY_MODEL | 支持 JSON 输出的模型名称 |
| KPL_QUALITY_API_KEY | 服务密钥，禁止提交仓库 |

每篇规则通过的候选一次模型请求，temperature=0、max_tokens=1600、timeout=60秒，不自动重试；超出120000字符的文章转复核，不用截断正文作准入依据。JSON 响应必须完整结束（finish_reason=stop）。这条 Python 路径不共享主站回执与预算系统，不能在生产环境无额度控制地批量开启；后续统一接入主站需经已有 providers/receipts 管道，不应绕过它。

不开模型仍可运行，但规则通过的内容只能待复核，没有新的自动精选。运行会联网抓候选网页，只有测试完全离线。运行命令与依赖见根目录 README。

## 评分策略

六维含义及分类权重见 [修改前审查/方案](ai-curation-review.md) 和 `prompts/curation-quality.md`。采用五个正向维度的分类加权总和，减0.5倍噪声，取整限制0–100。代码重算 quality_score 和 should_curate，不允许模型输出不一致的布尔值直接放行。70分只是初始门槛，不能理解为经过实测优化的最佳阈值。

- 短文不降级：完整 BP 因果和明确官方公告可通过。
- 长文不加分：重复名字、吹捧、夸张标题不能替代信息。
- 原创性与时效不同：转载仍有事实价值，但独特性降低；旧战术可凭参考价值入选。
- 完全重复正文：规范化空白/大小写后 SHA256 对比既有库与本批通过文章，独特性归零且总分封顶49，不重复入库。既有库缺指纹时从 offline.html 正文计算。没有 HTML 和指纹的旧条目暂时无法参与正文去重。
- 近似转载：由模型结合材料中的转载/重复证据评估；未实现全库语义相似检索，模型看不到完整历史库，不能可靠识别没有转载标记的近重复改写。
- 官方真实性：作者是未经认证的声明，评分要求正文证据；未新增官方域名/账号认证库或外部事实核验。不要把这一维度视为已经验证赛果真实。

## 元数据与审计

旧基础字段全部保留。新增字段示例（BP fixture 计算结果）：

```json
{
  "quality_score": 86,
  "quality_dimensions": {
    "information_value": 92,
    "analysis_depth": 90,
    "originality": 80,
    "timeliness": 70,
    "reference_value": 94,
    "noise_penalty": 5
  },
  "content_category": "tactical_analysis",
  "ai_reason": "提供具体BP时序、线权与资源因果证据",
  "should_curate": true
}
```

还新增 content_fingerprint、quality_evaluation（version/model/evaluated_at）、curated_category 和旧兼容 tag。目录继续按战队，不改成内容类型目录。INDEX.md 展示价值分和类型，历史未评分标明“未评分”。QUALITY_AUDIT.json 保存本轮通过文章及拒绝/待复核的结构化记录；规则拒绝没有伪造AI分，模型拒绝有完整维度与理由。AUDIT_REPORT.md 区分未准入和技术失败，不再声称已实现100%图片下载。

审计文件描述本次运行，不是长期追加历史；需要持久审计时可将每次运行产物归档。既有 articles/analyses/publications 数据库均未修改。导入脚本目前忽略新增质量字段，主站 API/前端不会自动展示它们，也不会自动用其约束主站发布。

## 测试结果

执行：

```bash
python3 -m pytest tests_py -q
python3 -m ruff check curator.py quality_scoring.py tests_py/test_curator.py tests_py/test_quality_scoring.py
python3 -m compileall -q curator.py quality_scoring.py
git diff --check
```

88个Python测试通过（包含原采集器和大家拉客户端回归）。五类核心样本：

| 样本 | 结果 |
|---|---|
| 不足800字的具体BP分析 | 通过，86分 |
| 超800字的粉丝吹捧 | 拒绝，0分 |
| 短官方赛事规程公告 | 通过，88分 |
| 标题党诱导关注 | 拒绝，0分 |
| 相同正文转载 | 独特性0、分数≤49、拒绝 |

其他覆盖：分类最低维度、阈值边界、噪声否决、旧战术参考价值、模型总分/布尔值不可越权、严格JSON字段/范围/类型、关闭/配置缺失/异常/截断响应、来源日期透传、全长正文保护、已有库保留、新metadata落盘、不同URL正文去重、异常页面及二次抓取变化。

测试模型输出固定，证明的是工程策略和契约，不证明真实模型能正确区分上述材料。没有外网调用、模型花费、真实采集或存量迁移。未运行主站数据库/前端测试，因为此次不修改该路径。

## 后续上线建议（按优先级）

1. 人工标注100–200条，包含短BP、短公告、长情绪稿、转载、机制分析及临界样本；分开发/留出集，统计查准率、查全率、误选/漏选类别，优先查准率。单独测实际模型的JSON成功率及注入抗性。
2. 样本校准后小批影子运行，只写评价，不自动入库；人审通过再开启自动准入。不得直接用模拟测试代替上线验收。
3. 单独设计主站集成：经已有预算/回执调用质量模型，将知识价值评价落 analyses.output 或新增独立字段，沿 publication 统一读取层公开；不能覆盖事件注意力或抽取完整度分数。导入时认证信源不能只靠战队目录推断。
4. 将近重复检索候选、官方账号认证信息提供给评分器；明确事实证据、舆情样本和转载增量，避免让模型猜历史。
5. 对历史库存先输出重审结果，再由管理员确认移出精选；不破坏性清库。完善版本化审计和成本额度约束后再做大规模生产运行。
