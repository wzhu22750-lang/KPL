# KPL 信源与内容组织改版：分阶段执行方案

状态：讨论稿，待确认后执行。本文仅规划产品、内容和运营规则，不涉及采集工具、数据库或代码实现。阶段时长、内容配比和验收样本均为建议，不代表已验证结果。

## 1. 改版目标与范围

产品定位：以争议热点吸引关注，以比赛事实提供背景，以圈内观点和社区趣评促进持续阅读的 KPL 内容聚合产品。

用户打开产品应快速回答：今天打了什么？圈里在吵什么？各方为什么争？有没有新回应？有什么好笑的？

两条核心组织主线：
- 比赛主线：比赛日 → 大场（系列赛）→ 小局 → 关键节点。
- 话题主线：争议起点 → 各方观点及依据 → 回应 → 新进展 → 阶段性结论。

争议内容优先，不等于编造对立或按辱骂程度排序。允许呈现真实冲突，避免断章取义、无依据定罪、泄露隐私和引导围攻。流量提升是待验证假设，不是保证。

### 1.1 用户明确提出的需求

| 编号 | 需求 | 对应安排 |
|---|---|---|
| R1 | 联盟官方比赛、活动与发帖，覆盖 B站、微博、公众号 | 官方信源池与事实内容 |
| R2 | 各俱乐部微博的赛况、选手活动、运营活动 | 全俱乐部覆盖、分层展示 |
| R3 | 二路主播、官方主播、解说的采访与观点；整理大流量名单 | 人物信源池，覆盖其相关公开平台 |
| R4 | 虎扑帖子和评论、微博超话、B站与小红书评论中的热点 | 社区发现与话题整理 |
| R5 | 文豪、梗、趣评、粉丝争议等内容 | 趣评精选与争议专题 |
| R6 | 更聚焦有矛盾冲突的吵架话题，以争取流量 | 首页争议优先、持续追踪、试运行评估 |
| R7 | 同一大场内零散战报、操作、MVP 聚合 | 大场唯一主档、小局分章 |

### 1.2 建议补充的范围

- 选手、教练等当事人的公开表达，避免只听官方和旁观者转述。
- 电竞媒体、采访记者、数据作者、战术作者与优质二创作者。
- 低流量但有价值的分析，以及小俱乐部圈内的重要动态。
- 以下展示配比、菜单名称和阶段验收门槛为建议，尚未获得用户逐项确认。

## 2. 信源体系：按发布者分组，按内容性质筛选

| 信源组 | 覆盖内容 | 使用原则 |
|---|---|---|
| 联盟与赛事官方 | 赛程、首发、赛果、积分、赛制、处罚、采访、活动 | 赛事事实基础；普通运营帖不自动获得高优先级 |
| 俱乐部官方 | 战报、阵容、人员变动、备战、活动、声明 | 全队覆盖；重要事项进主流，日常进入战队动态 |
| 选手与教练等当事人 | 公开回应、采访、直播、复盘、职业动态 | 区分本人表态、官方说明和外界推测；不搜集私人信息 |
| 主播、解说、评论员 | 二路解说、战术观点、采访、名场面、争议发言 | 同时建影响力名单与内容价值名单，不只看粉丝量 |
| 媒体与优质创作者 | 深度采访、数据、战术、历史、二创 | 补足独家信息和解释力；质量与流量分开判断 |
| 社区与粉丝 | 虎扑帖评、超话、B站/小红书评论等 | 发现冲突、趣评和观察；明确平台与圈层，不代言全体观众 |

主播候选平台包括微博、B站、小红书、抖音等，具体平台按账号公开活动情况确定。平台覆盖是目标清单，不代表当前均可稳定获取。

名单记录：人物/组织、身份、公开账号、平台、关注队伍、内容特长、活跃情况、代表样本、是否一手出处、转述习惯、优先级、最近复核时间。

优先级：
- 核心持续关注：联盟、所有参赛俱乐部、主要高影响力人物及重点社区。
- 高价值精选关注：稳定产出采访、分析和二创的作者。
- 事件临时关注：因某事件出现的当事人、原作者和新账号，事件结束后复核是否长期保留。

账号身份只说明谁发布，不保证其所有说法都成立。官方名单可证明谁上场，不能自动证明轮换原因；多个搬运账号也不构成多个独立证据。

### 2.1 获取资源与频率优先级

依据用户目前对获取难度的判断，将微博作为主通道；这是资源配置决策，不代表已验证所有微博入口均更稳定。账号动态和超话访问情况分别评估。

| 渠道 | 角色 | 建议频率策略 |
|---|---|---|
| 微博官方、俱乐部、人物账号 | 事实与观点主通道 | 高频关注；比赛前后、重要公告和当事人回应期间重点更新 |
| 微博超话、虎扑帖子与评论 | 争议与趣评主通道 | 活跃时段重点关注；热点出现后追踪增量，降温后回落 |
| B站 | 原始视频、采访、二路切片与评论补充 | 重点账号常规检查，涉及热点或缺失上下文时优先补充 |
| 小红书、抖音等 | 独特观点、名场面与跨平台传播补充 | 精选账号与事件触发，先不追求全量覆盖 |
| 公众号 | 深度文章、长采访、独家公告补充 | 降为低频巡检，可先试每日一次；发现独家重要内容时临时提高优先级 |

原则：同一内容微博已有完整版本，不重复投入高成本渠道；公众号若提供新增事实或完整采访，则保留其独特价值。微博获取优先不等于微博内容天然加分。获取成本与内容价值分开处理，发现的重要独家公告不因低频策略而被主动压低推荐。

## 3. 内容与展示规则

### 3.1 争议话题作为主要推荐内容

优先关注：
1. 首发与替补、轮换、转会、退役及人员安排争议。
2. 选手表现、队内定位、资源分配、胜负责任之争。
3. BP、战术、教练指挥与临场决策争议。
4. 主播、解说、选手之间的公开观点冲突与回应。
5. 裁判、赛制、处罚、赛程公平性讨论。
6. 俱乐部运营、商务、票务、粉丝待遇争议。
7. 队伍与选手比较、历史地位、预测被结果反转等话题。

话题值得推荐的理由：有清楚的争议对象、实质不同的立场、可回溯的原始内容，并出现讨论升温或新进展。单纯辱骂堆积不等于好话题。

排序同时考虑：讨论增长、实质分歧、当事人回应、新增信息、跨圈传播及 KPL 相关性。另行检查事实可靠程度，不让热度替代可信度。

不可直接把不同平台的点赞评论量当作可比数值；同时观察全联盟热度和相对该战队/账号平常水平的变化。跨平台重复搬运、刷屏和同一批账号重复表达不能误判为共识扩大。

### 3.2 每个争议话题的标准阅读结构

- 一句话说明：到底在争什么。
- 已确认背景：发生了什么，哪些尚未确认。
- 争议起点：原始发言、名单、比赛操作或公告。
- 主要立场：各方主张、依据与争议焦点，不强行二分。
- 当事人回应：若没有公开回应，直接说明未发现回应，不推断其态度。
- 进展时间线：起点、传播、回应、新证据、澄清。
- 代表性评论：说明来自哪个平台/圈层、选取理由，必要时淡化普通用户身份；不是民意调查。
- 相关趣评：单独标注玩笑、反讽和二创，不混入事实段落。
- 当前状态：持续争议、等待回应、出现澄清或暂无新进展。
- 原始出处：便于核对语境。

可以用有张力的标题，但张力来自真实分歧，而不是捏造内幕或借疑问句传播未经证实的指控。更正、澄清回写原话题并清晰显示，不只另发一条低曝光消息。

同一话题没有实质新进展，不因增加一条骂评就重新包装上榜。

### 3.3 大场比赛聚合

以一场系列赛为唯一主档，不仅按对阵双方归并，还要区分赛事、阶段、场次与日期，避免同队多次交手混在一起。

比赛日按预定赛程展示各大场，并标明未开始、进行中、已结束、延期或取消。实际开始时间与预定时间有变化时说明。

每场主档包含：
- 赛事、阶段、双方、赛制、预定与实际比赛时间、当前状态。
- 赛前首发与必要背景。
- 按局次排列的小局结果、大比分变化、MVP、重要操作。
- 全场最终结果与可确认的晋级/积分影响。
- 赛后采访、复盘、相关争议与趣评。

BO5、BO7、BO9 根据具体赛事和阶段确认，不永久写死“所有季后赛/所有决赛都采用某赛制”。不预设系列赛必须打满。

组织原则：
- 主时间线按事件发生顺序，不按发帖顺序；同时保留原帖发布时间。
- 无法确认具体局次或操作先后的内容保留待确认状态，不补造比赛时间。
- 同一局多账号战报合并为一个事实节点，保留来源入口。
- 同一局的不同精彩操作、独到点评、优质视频不作为重复内容删除。
- 次日复盘仍关联原场比赛；跨午夜赛事保持同一主档，比赛日归属采用赛事赛程口径。
- 信息流内一场一张比赛主卡，随进程更新，不因每局战报反复创建主卡。
- 重要更正同步修正当前比分/结果，保留更正记录。

以用户的 AG 对 LGD 示例说明：
- “AG以1:0拿下首局”进入第一局结果。
- “LGD第三局获胜，断雨杨戬获MVP”进入第三局结果与MVP。
- “九尾沈梦溪越塔三杀”确认所属局次后进入该局精彩操作，不能仅凭标题猜局次。

上述为用户提供的归类示例，非本文核验过的真实赛果。

主时间线默认精简，延伸观点、视频和评论可展开。比赛内出圈的争议可以在热点区独立推荐，但回链到相关比赛及小局；跨多场的轮换争议独立成话题，关联多场比赛，不强塞到某一场。

### 3.4 建议的用户入口

- 热点：默认优先展示争议、回应、反转等有新进展的话题，穿插名场面与趣评。
- 今日比赛：按赛程查看大场与小局时间线。
- 关注动态：选手、战队、主播的相关公开动态。
- 精选观点与趣评：便于回看分析、梗与二创；是否独立成菜单在试读后决定。

比赛入口保持容易找到，不要求用户从大量争议帖中寻找比分。

推荐内容初始试验配比：争议热点约50%、其他重要动态约20%、观点复盘约15%、趣评二创约15%。每条推荐只计一个主要类型，固定比赛入口不计入配比。此配比不是硬配额，缺乏真实热点时不以旧闻或无依据爆料补足。

### 3.5 AI 评分改版：内容价值、官方身份与讨论热度共同决定推荐

以下是待样本校准的建议方案，不是现行实现或已经验证的权重。

先做 KPL 相关性、出处与可用性检查，再评估推荐价值。明显无关、纯引流、无实质内容的辱骂不靠加分挽回；重复素材附到原比赛/话题，不重复占推荐位。

建议采用100分结构：基础内容价值0—70分 + 官方来源加分0—10分 + 观测热度加分0—20分 − 噪声扣分0—30分，最终限制在0—100分。

基础内容价值按类型评价，不用同一套“分析深度”要求所有内容：
- 公告/战报：事实重要性、新信息、时效、对赛事的影响。
- 争议/观点：分歧清晰度、依据与上下文、解释力、新回应或进展。
- 分析/复盘：论证、独特观察、参考价值。
- 趣评/二创：趣味、原创性、圈内语境与可理解性。
- 日常/活动：对相关关注人群的实际价值。

官方来源加分建议：
- 已核验联盟或俱乐部账号的一手赛程、首发、赛果、规则、处罚、人员公告：+8—10。
- 官方原创采访、赛事内容、活动资讯：+3—6。
- 普通应援、重复海报、纯商务推广：+0—2，不仅凭身份进入首页。
- 搬运官方内容不继承官方身份加分；本人回应属于一手表达，不自动等同联盟/俱乐部官方。其信息价值在基础分中体现。

观测热度加分建议：
- 结合可获取的互动量、增速、不同参与者数量、讨论持续性和跨社区传播，给予0—20分。
- 超话、虎扑的真实高热讨论可得到明显提升，但“来自超话/虎扑”本身不加热度分；其他平台同样适用。
- 比较同平台、相近发布时长和相近圈层的表现，同时保留全圈传播信号；不直接比较微博转评赞与虎扑回帖数。
- 记录观测时间与可用指标，数据缺失标记“热度未知”，不推断为冷门，不让 AI 根据标题或账号名编造热度。缺少增长历史时不声称增长迅速。
- AI 负责内容判断，热度加分必须引用实际观测；原始数据不足时展示评分覆盖情况，不将暂未获得热度加分误作低质量结论。

噪声扣分针对标题夸张、断章取义、重复拼贴和刷屏式低信息内容；严重失实或隐私侵害转人工复核或不发布，不只是扣几分继续推荐。

评分分两个层级使用：
- 素材级：判断是否值得保留为比赛或话题的证据、观点、视频或趣评。
- 事件级：决定大场或话题的推荐顺序，综合新增信息及去重后的讨论，不把每条战报分数相加，不因搬运账号多而无限加分。

推荐分与可信状态独立：高热传闻可以作为“出现了什么讨论”呈现，不能升级为已证实事实。赛程、首发、每局结果、最终赛果及更正属于比赛完整性必需信息，即使互动少也应收录到主档；是否上首页另行判断。

## 4. 分阶段执行

执行顺序：阶段一 → 阶段二 → 阶段三、四可并行 → 阶段五 → 阶段六。阶段四无需等待全部比赛整理完成；争议主线应尽早试做，而不是等到改版末期才补上。

### 阶段一：确认定位与内容边界

目标：明确这是“争议热点优先的 KPL 内容聚合”，不是纯公告站，也不是无差别搬运骂战。

任务：
1. 确认六组信源范围和四种用户阅读需求。
2. 确认首页争议优先与比赛独立入口。
3. 明确事实、观点、传闻、玩笑四类标识。
4. 明确日常运营、商务推广、重复应援的降权规则。
5. 以首发争议、普通战报、文豪梗帖各做一份纸面示例。

交付物：内容定位说明、展示优先级、内容边界、三个示例。

验收：用户认可定位；每个示例都能回答“放哪里、为什么推荐、怎样避免重复与误导”。

### 阶段二：建立信源名单与对照样本

目标：知道关注谁，并获得可用于后续验收的真实材料。

任务：
1. 核对联盟和所有参赛俱乐部的公开官方账号。
2. 建立选手/教练重点名单。
3. 建立二路主播、官方主播、解说的影响力与内容价值两类名单；具体数量由实际调研决定，不声称凭印象覆盖全部头部。
4. 补齐媒体、数据/战术作者、二创作者及重点社区。
5. 选取近期完整比赛日与历史争议，保留原始出处和上下文。

6. 为每个渠道标明常规频率、比赛/热点加频条件、获取成本与独家内容价值，确定微博主通道及公众号低频补充策略。

交付物：信源目录初版、渠道频率优先级表、覆盖缺口清单、真实样本包。

建议样本：至少一个包含三场系列赛的比赛日，另选 BO7/BO9 案例检查适配；至少五个争议案例，涵盖首发、表现、BP、发言、运营中的多种类型；包含普通运营帖和重复战报作为反例。

验收：官方账号经过身份核对；重点二路人物有明确入选依据；每个样本能找到出处，访问缺口显式列出，不编造缺失材料。

### 阶段三：先解决比赛碎片化

目标：把原来大量分散战报整理为完整大场档案。

任务：
1. 按比赛日建立系列赛目录。
2. 把首发、每局结果、操作、MVP、全场赛果分别归位。
3. 合并重复事实，保留独特内容与多源出处。
4. 处理晚发战报、次日复盘、同队重复交手、局次不明和跨午夜等情况。
5. 产出精简时间线与展开阅读两种版本，进行试读。

交付物：完整比赛日样稿、大场详情样稿、聚合与异常处理规则。

验收：样本中的三场比赛对应三张主卡；所有已确认的小局结果归属正确；没有将局次不明操作猜入某局；同一事实不反复占主时间线；读者能快速找出胜负、比分变化与关键节点。未知或缺失的MVP等信息明确留缺，不要求凭空补全。

### 阶段四：建立争议热点产品

目标：让用户看懂冲突并追踪后续，而不是只看到散落的吵架截图。

任务：
1. 对五个争议样本整理完整话题档案。
2. 展示真实存在的主要立场及依据，不强行制造势均力敌的“两派”。
3. 区分事件原始出处与后续搬运，追溯切片上下文。
4. 整理当事人回应、澄清、尚未证实的问题及相关比赛。
5. 单列代表性趣评，避免正文成为辱骂合集。
6. 形成何时首次推荐、何时因新进展再推荐、何时停止刷新的规则。

交付物：争议话题样稿、热点选择标准、标题规范、更新与更正规则。

验收：读者能回答“在争什么、各方依据是什么、哪些未知、最新进展是什么”；每个事实和引语可追溯；无回复不被解释为默认；不能用互动量或转发数量证明传闻成立。

### 阶段五：整合首页并小范围试读

目标：验证争议优先是否更有吸引力，同时不牺牲查比赛和读事实的体验。

任务：
1. 用相同样本做“较均衡”与“争议优先”两个首页编排版本。
2. 保持比赛入口稳定，调整争议、观点和趣评的推荐位置。
3. 检查一个热门大场是否过度霸占版面；同一话题重复转载不单独推送。
4. 让不同关注战队的读者试读，完成找赛果、理解争议、追踪回应三个任务。
5. 询问哪些内容想点、哪些重复、哪些像引战标题，记录理由。
6. 用同一批样本对照旧评分与新评分，逐项解释基础分、官方加分、观测热度与扣分；缺失指标明确标注。
7. 检查官方低热重要公告、高热社区争议、普通官方广告、低热优质分析、缺少热度数据的独家文章及重复战报，避免单一身份或互动量垄断推荐。

交付物：首页编排方案、评分规则初版及新旧排序对照、试读记录、问题清单、首轮调整结论。

验收：读者能找到比赛主档，区分事实与评论，进入感兴趣的话题并找到原始出处；优先解决误归档、断章取义与重复展示。若只有内部试读，只能得出可读性与偏好结论，不能声称流量已提升。

### 阶段六：试运营、复盘与扩充

目标：用实际使用情况决定扩哪些信源、提高哪些内容权重。

任务：
1. 建议先覆盖连续两个比赛周，包含比赛日和休赛日；样本不足则延长观察。
2. 记录热点发现是否及时、比赛归档是否完整、后续回应是否跟上。
3. 同时观察阅读收益和质量成本，不以评论吵得多作为唯一成功标准。
4. 扩充遗漏的高影响力人物、优质小作者与社区；淘汰重复搬运、无关内容多的信源。
5. 调整推荐配比、AI 评分权重与渠道频率，并输出下一版需求；检查微博优先是否漏掉困难渠道的独家重要内容。

交付物：试运营复盘、信源目录第二版、推荐规则修订、后续实施优先级。

验收维度：
- 吸引力：在相近曝光条件下比较打开率、继续阅读、返回查看后续、收藏或分享。
- 比赛体验：查比分与关键节点是否顺畅，归错大场/小局与重复主卡是否减少。
- 话题质量：事实及引语能否追溯，澄清是否同步，读者能否分清推测与证实。
- 内容健康度：重复、误导投诉、屏蔽、无实质新信息的再推荐是否增加。
- 覆盖：是否过度集中于少数明星队，重要冷门事件是否被遗漏。

具体量化门槛先测旧版基线后确定；小样本结果只能作为方向信号。出现归档错乱或误导性争议稿时先修正，不以增长指标抵消。

## 5. 日常运行节奏

| 时段 | 主要工作 |
|---|---|
| 赛前 | 建立大场入口、更新首发和赛前争议背景 |
| 每局结束 | 更新小局结果、大比分、确认过的MVP和关键片段，不新建重复大场卡 |
| 全场结束 | 汇总结果、赛后采访、关键分歧与趣评 |
| 次日 | 补充复盘、回应、澄清，仍关联原场比赛或原话题 |
| 休赛日 | 跟踪人员变化、公开活动、持续争议与优质长内容，不翻炒旧吵架凑量 |

## 6. 第一轮完成边界与下一步

第一轮应交付：核心信源目录、完整比赛日样稿、五个争议话题样稿、首页编排样稿及试读结论。

暂不追求：全网所有账号与评论、全量历史回填、每条运营帖上首页、所有传闻自动公开、立即证明流量增长。
