## 5. 关键决策与踩过的坑（接手必读）

1. **Supabase SSL**：pg-boss 用 `pg` 驱动，把 URL 的 `sslmode=require` 当 verify-full，对 Supabase 自签 CA 验链失败 → worker 崩溃。已修：`config.ts` 内置 Supabase 根证书（`deploy/supabase-ca.pem`），`queue.ts` 用 `ssl: { rejectUnauthorized: true, ca }` 做**完整校验**（比关校验更安全）。其它私有 CA 的 PG 用 `NODE_EXTRA_CA_CERTS`。**不要退回 `uselibpqcompat` 之类的关校验写法**。
2. **Supabase Session Pooler 上限 15 连接**：四个连接消费者（api/worker/一次性脚本/pg-boss）加起来容易超。已设 `DATABASE_POOL_MAX=3`；pg-boss 硬编码 `max:4`（`jobs/queue.ts`）。**被 kill 的进程会残留会话 1–2 分钟**——遇到 `EMAXCONNSESSION` 先等 1 分钟再重试，不要急着加连接；一次性脚本用 `DATABASE_POOL_MAX=1`。
2b. **pg-boss 的 SSL 覆盖坑**：node-postgres 的 `ConnectionParameters` 用 `Object.assign({}, config, parse(connectionString))`——**URL 解析结果会覆盖显式传入的 `ssl` 选项**。所以给了 `ssl.ca` 时必须同时从连接串剥掉 `sslmode`（`queue.ts` 的 `bossConnectionString`，提交 62bab79），否则报 `SELF_SIGNED_CERT_IN_CHAIN`。
3. **跨洋写库慢**：Supabase us-east-2 单次往返 ~250ms，逐条写入约 15s/局。**批量回灌一律走"本地库 + sync-kb-to-supabase.sh"**，不要在远端直接跑 import 脚本。
4. **并发双写**：worker 自动同步与回灌脚本可能同时补同一局，先清后写交错会撞 `bp_actions_pkey`。已修：`upsertGame` 单事务 + 对局级 advisory lock（提交 066cb6c）。
5. **赛季命名**（`kb/upsert.ts` 的 `seasonMeta`）：不能只看 league_id 尾号——2026 年起 0002=KCC 杯赛、0003=夏季赛、0004=年度总决赛。按官方 `cc_match_id` 前缀（KPL…S1/S2/S3、KCC）判定，序号只是回退。`latestSeason` 按"最近比赛日期"排序而非 id。
6. **BO9 存在**：2026 KCC 有 bo=9（迁移 0060 已放宽约束）。
7. **camp1=蓝方是站内约定**：官方数据不暴露蓝红颜色，`matches.team_a_id` 固定对应 camp1。所有 BP side 由此推导。
8. **选手 slug**：中文昵称直接用昵称作 slug（`/players/清融`，URL 编码后可用）；拉丁 ID 选手用 ID。换队后旧履历 `left_at` 需要人工/脚本补。
9. **前端构建的坑**：React Router 构建器拒绝**未使用**的 `.server` 模块导入（`import { apiGet, loadOr404 }` 里没用 apiGet 也会构建失败）——新页面只导入真正用到的。
10. **Mimosa 安全钩子**：写文件会被静态扫描，`kb/upsert.ts` 里避免"模板/正则拼接"模式（会误报命令注入）；SQL 全部走 postgres.js 参数绑定（安全约束要求）。
11. **数据源无官方契约**：`prod.comp.smoba.qq.com` 是非承诺接口，字段/路径可能随赛季调整。适配器集中在 `sources/esports.ts` + `kb/upsert.ts`，上游变化只改这两处；健康状态看 `fetch_runs` 表。
